## Implemented

- Shared ASC Music Match normalizes titles and accents, accounts for features and available identifiers, recognizes recording variants, requires exact normalized title identity for automatic availability, and leaves ambiguous versions for review.
- Web playlist import supports CSV, text, manual creation, and Spotify's official PKCE Web API path when configured. It preserves full lists, reports availability/missing/possible/duplicate states, and does not fabricate data when a provider is unavailable.
- Web local audio selection/player, metadata indexing, missing-track center, library re-check, and Google Drive folder-picker/indexing/playback flows are implemented. Drive indexing uses revision checks, bounded concurrency, paginated Changes API checkpoints scoped to the selected account folder, cancellation, and safe full-tree fallback when folder topology changes; removed and moved files are reconciled.
- Worker/D1 stores playlist and library metadata (not audio), verifies Cloudflare Access and Supabase asymmetric JWTs, namespaces Supabase identities, scopes private rows by verified subject, limits JSON request bodies, and batches playlist writes. Public discovery adapters report provider origin/update time and surface unavailable sources.
- Android Compose/Media3 supports local document-provider indexing, playback, text/CSV playlist import, match review states, and a background media session. Metadata indexing is stored in SQLite; existing SharedPreferences library metadata is migrated on first load.
- Android local library now supports SAF folder selection with persisted read access, bounded recursive scans, multi-file selection, metadata/artwork extraction, missing-tag fallbacks, duplicate identification, startup/manual rescans, index-only removal/exclusions, and reconciliation of added/removed folder documents.
- Android SQLite v6 now preserves the shared physical library (`tracks`, SAF folders, exclusions, metadata) while creating account-scoped playlists, playlist tracks, favorites, playback history, playback queue and playback preferences. Existing v1–v5 personal tables remain untouched as legacy data and are not assigned to any account. The Android UI and playback service now use the authenticated account-scoped methods; runtime validation remains pending.
- Android now supports app-link handling for Supabase signup confirmation and password recovery, validates callback destination/type, fetches the user profile over HTTPS before storing session tokens, and can update the password. These flows are not yet tested using a real email or account.
- The workspace's ignored `.env.local` and `android/supabase.properties` contain only the supplied public project URL/publishable key; `backend/wrangler.toml` contains the real public Supabase URL. No service-role key or signing secret was requested, used, or stored.
- Vite now loads root-level environment configuration for both application code and generated CSP; the production Web bundle and Android Release BuildConfig were checked for the configured public URL/key without printing them.
- Read-only public Supabase checks on 2026-11-11: JWKS available with an ES256 P-256 key; public Auth settings report signups/email enabled. The owner subsequently confirmed that the dashboard contains Site URL `http://localhost:5173/`, Web redirect URL `http://localhost:5173/`, Android redirects `ascmusic://auth/confirm` and `ascmusic://auth/recovery`, and the Email provider enabled. These dashboard settings do not validate any user flow. PostgREST schema enumeration was unavailable with the publishable key. Supabase Postgres stores no ASC Music data in this architecture; sync records use D1, so no Supabase application-table/RLS migration was added.
- Android Media3 service and Compose controls now cover play/pause, seek, previous/next, volume, shuffle, repeat-one/repeat-queue, queue display, persisted queue restoration, history, and background MediaSession notification/lock-screen integration in code.
- CSV parsers support quoted/multiline values and enforce playlist/file limits. Production CSP headers are generated with only the configured API origin added.
- Round-two fixes addressed Android duplicate selections and stale/error handling, ambiguous recording-version matching, Worker request-size and query behavior, Web local re-verification/reconciliation, and misleading partial Spotify imports.
- Mobile UI follow-up: compacted the mobile hero spacing, made Web bottom navigation horizontally scrollable with single-line labels and 52px touch targets, enabled 320px layouts, and made Android navigation horizontally scrollable without text wrapping. ASC Match now distinguishes indexed files from analyzed playlist tracks and separately counts found, missing, review-needed, and duplicate matches; empty analysis shows no calculated percentage.
- Android release preparation: moved to AGP 8.13.2/Gradle 8.13 and API 36, enabled R8 and resource shrinking, made version values configurable, and added release signing exclusively through process environment variables. No production keystore is stored in the workspace.
- Android's SAF folder action is now the primary import route; rescans reuse unchanged metadata, honor index exclusions, and keep queue/index state consistent when tracks or folders are removed. A library search field covers title, artist, album, and file name.
- SAF rescans now catch provider cursor/read failures and preserve prior indexed tracks when a scan is incomplete. Folder permission status is checked against persisted read grants, with a reauthorization action for folders whose grant is missing. Pure logic tests cover incomplete-scan reconciliation, stale-grant reporting, and permission-persistence failure handling; an instrumentation test checks the system folder-tree picker contract.
- Legacy Cloudflare Access JWT validation remains supported for compatibility; Supabase is the selected end-user identity. Worker bearer authentication validates the configured identity according to JWT issuer and signature.
- Android backup/data-transfer exclusions explicitly keep the local index and preferences on-device. The Media3 trust check is annotated for its unstable API contract.
- Supabase Auth is the chosen user identity, separate from Cloudflare Access. The Worker validates ES256/RS256 JWTs through the Supabase JWKS, requires the authenticated audience/role, and derives a `supabase:` namespaced tenant from the verified subject. Existing Access JWT verification remains for legacy routes.
- Web now has Supabase registration, sign-in/out, session refresh, recovery request, Bearer Worker requests, account-keyed local state, and an IndexedDB outbox/version/cursor for playlists, favorites, history, and playback settings. Playback queue and Drive folder selection are also account-keyed; the physical IndexedDB music library remains shared by device policy. Remote updates are replay-safe, while unsupported record types fail without advancing the cursor. Local data is not automatically uploaded at login. Authorized Spotify playlist listing/import uses the same official PKCE token and never stores a client secret.
- Provider error handling now distinguishes Spotify authorization/entitlement/rate-limit responses and Google Drive permission/quota failures, preserving a user-actionable recovery path without retry storms.
- Android now has Supabase email registration/sign-in/out, refresh and recovery-request calls, AES-GCM session storage backed by Android Keystore, a basic account UI, HTTPS Worker sync, SQLite outbox/cursor/version persistence, retryable operation IDs, playlist/favorite updates, account history events with real millisecond timestamps and metadata snapshots, and coalesced playback-setting outbox records. Remote history/settings payloads now map to the Android account tables. This code has not been exercised with a configured Supabase project or Worker.
- Android now contains configurable native Google Drive and Spotify PKCE clients. Provider tokens use separate AES-GCM Android Keystore stores; Google refresh/revocation, Spotify refresh, callback state validation, paginated folder/playlist APIs, provider disconnect, rate-limit handling, and cancellation checkpoints are implemented without committed client IDs.
- Android Drive folders can be selected from paginated remote folder results, indexed into the shared physical library using stable `gdrive:<fileId>` identities, and played through a Media3 range-aware data source without downloading the complete file before playback. Android Spotify playlists can be listed and imported into the authenticated account-scoped playlist store.
- Android provider and Worker synchronization UI now exposes connection states, progress text, cancellation, and retry-safe interruption behavior. A cancelled provider/library operation commits no partial index replacement; a cancelled sync retains its outbox/cursor state for retry.
- Android playback changes now enqueue account-scoped shuffle, repeat, and volume settings with coalescing; library metadata changes enqueue stable metadata-only records without uploading SAF URIs or audio. Remote conflict handling now offers local rebase or remote acceptance in the Android UI.
- Web library metadata now uses the account sync contract for signed-in sessions while preserving the legacy endpoint for anonymous mode. Web conflicts now expose explicit actions to accept the remote record or rebase the local operation against the remote version.
- Web now offers an explicit, non-destructive import of preserved anonymous legacy playlists, favorites, and history into the signed-in account; legacy keys remain untouched and no import occurs without user action.
- Web playback history is browser-local and bounded to 100 metadata-only entries with millisecond timestamps; new playback history is queued for account sync when signed in. Drive token-expiry handling clears stale in-memory credentials.
- Worker `/api/sync` provides per-user versioned entities for playlists, favorites, history, library metadata, and allowlisted settings; request-fingerprinted idempotent operation IDs, optimistic conflict responses, append-only paginated events, and explicit tombstones are implemented. It stores normalized metadata only and rejects path-like entity IDs. Client wiring is partial; there is no cross-client end-to-end test or live service validation.

## Known limitations and release gates

- Android has Supabase login/session refresh and partial playlist/favorite/history/library/settings sync; native Drive/Spotify wiring is implemented but remains unvalidated against provider accounts. Android now offers explicit legacy-data import with playlist collision remapping while preserving legacy tables. Legacy history entries without timestamps are imported using the import time and require product validation. Password-reset link completion remains externally unvalidated. The Supabase dashboard base configuration is recorded, but no authentication flow has been tested and no Worker deployment is configured.
- Real Drive permission/revocation, Spotify API entitlement/OAuth, provider availability/quotas, and remote D1/Access behavior require owner credentials and live services. Native provider client IDs, exact provider redirect registrations, and Google Drive folder scope configuration remain external inputs; no provider secret is stored in the project.
- Web and Android now call `/api/sync`, but no automated end-to-end sequence has demonstrated Android → Worker → Web → Worker → Android. Android remote pages are applied atomically with account state, entity version and cursor; conflict resolution offers explicit local-rebase/remote-accept actions but has not been validated against a live service. Web IndexedDB/outbox behavior and the new Android SQLite v6 migration still lack executed tests.
- The emulator validated SQLite behavior, generated-WAV Media3 playback, and the folder-picker contract. Real SAF selection/permission persistence, recursive indexing of user files, audio-format compatibility, service notification/lock-screen controls, interruptions, and restart recovery remain unvalidated on physical hardware. UIAutomator folder-screen inspection was blocked by an emulator system-UI ANR.
- Web Drive re-check now consumes paginated Changes API checkpoints for ordinary file changes and falls back to a complete tree walk for structural folder changes. Android Drive playback uses range requests through Media3; Web playback remains buffered transiently and its cancellation UI remains limited to the connector-level abort hook.
- The configured Worker database, Access team/audience, deployment domains, provider secrets, and production signing key are placeholders or absent. The release build is unsigned and must not be distributed.
- Automated browser E2E, signed release distribution/update flow, playlist collaboration, and independent penetration testing remain outstanding.

Do not represent external integrations, shared sync, or device-specific playback as production-ready until tested against the corresponding real service/device.

## Fase 1.1 — integração Android do isolamento por conta

- `LibraryDatabase` está na versão 6. A migração adiciona snapshots de título, artista e álbum ao histórico account-scoped, sem apagar tabelas antigas nem atribuir dados legados.
- `MainActivity` deixou de usar as APIs globais para favoritos, playlists, histórico e carregamento de estado pessoal. Sem sessão válida, esses dados não são exibidos nem gravados.
- `MusicPlaybackService` resolve a sessão diretamente pelo `SecureSessionStore` antes de restaurar ou persistir fila e histórico. Cada gravação assíncrona captura o proprietário ativo e revalida a sessão, evitando que uma troca de conta associe um snapshot antigo à conta nova. A troca de conta solicita recarga do estado do player; o estado persistido anterior permanece no banco.
- `WorkerSyncClient` confirma que o proprietário atual permanece igual durante toda a sincronização. Aplicações remotas reconhecidas atualizam tabelas account-scoped, entidades remotas, versões e cursor numa transação única.
- As APIs globais antigas permanecem somente para compatibilidade com bancos legados e testes de regressão. Não são mais chamadas pelo fluxo Android principal.
- Foram preparados testes para snapshots de histórico após remoção da faixa, upsert de playlist sem apagar outras playlists e rollback conjunto de página remota/cursor. Eles ainda não foram executados.
- A integração real Supabase/Worker, troca de contas em dispositivo, reprodução após reinício e validação em hardware continuam dependentes de execução posterior dos testes autorizados.
